# RedPen — контекст проекта для агента

RedPen публикует постраничный критический разбор школьного учебника «История
России. 11 класс» (Мединский/Торкунов): поверх изображений страниц —
кружки-аннотации с фактчеком, разбором манипуляций и умолчаний. Прод:
https://medinsky.net (сайт) + https://api.medinsky.net (API редактирования).

## Главный инвариант — сайт полностью статический

Опубликованный сайт — самодостаточный набор файлов: раздаётся любой статикой,
копируется на флешку, работает офлайн. **Просмотрщик никогда не обращается к
API** — аннотации/текст/картинки только из статических файлов по относительным
путям. API и БД обслуживают исключительно редактирование (`?editor=1`) и кабинет
(`/cabinet/`). Любая доработка, дающая просмотрщику сетевую зависимость, не
принимается. Подробнее: `docs/README.md`, раздел «Ключевое ограничение».

## Три репозитория (независимые, без submodules)

- **этот** (`redpen-infra`) — скрипты, шаблоны фронтенда, API, тесты, доки;
- `redpen-content/` (рядом или внутри) — исходники: картинки, текст,
  markdown-аннотации, черновики;
- `redpen-publish/` — собранный статический сайт (он же офлайн-артефакт;
  push сюда = публикация контента).

## Как устроено (после этапов 0–3, июль 2026)

```
Редактор/кабинет ──▶ API (FastAPI, scripts/api/) ──▶ SQLite (канон:
                       auth: Google GIS + роли        annotations + history +
                       viewer/editor/admin, CSRF      users/sessions, том redpen_db)
                                │
                                └─▶ publisher.py: на каждую мутацию рендерит
                                    «голый» JSON-массив annotations/page_NNN.json
                                    в том redpen_public → правка сразу на сайте
content-sync: публикует статику из git redpen-publish, НО каталоги */annotations/
исключены (их владелец — API); аннотации в git-снапшот попадают обратной
синхронизацией рендера (см. deployment-log, запись 2026-07-10).
```

Ключевые факты, на которых легко ошибиться:
- формат опубликованных аннотаций — «голый» массив `[{id,text,annType,coords}]`;
  `serverPageSha`/статусы живут только в API/БД;
- черновики (`status='draft'`) не попадают ни в статику, ни в анонимные ответы;
- id аннотаций уникальны в пределах страницы, не глобально;
- ключ страницы — файловый (`"006"`, `"000"`, `"-01"`), в БД `page_num` TEXT;
- нумерация для читателя — по манифесту `pages[{file,label}]` в metadata.json
  (`?p=A1`, `?p=17`); легаси `?page=N` работает всегда (см.
  `docs/page-addressing-proposal.md`);
- API-контейнер работает под uid 10001 — права на томах выдаются явно
  (грабли описаны в памяти и deployment-log).

## Контент-конвейер и агент-аннотатор

Аннотации пишет **агент-аннотатор** по промпту `docs/annotation-agent-prompt.md`
(это главный «субагентский» промпт проекта, поддерживай его актуальность):
один запуск = один параграф из `redpen-content/<docId>/paragraphs_list.txt`;
перед запуском нужны картинки с сеткой (`python3 scripts/make_grid_images.py`).
Агент смотрит `images_with_grid/`, цитирует по `text/*.json` (внимание: сдвиг
нумерации текстовых файлов +1), обязан выполнять «протокол умолчаний» (grep по
всему корпусу текста перед любым «в учебнике не сказано») и верифицировать
источники. Результат — черновики в `redpen-content/<docId>/annotations_draft/`
(`page_NNN.md` в формате `~~~meta` + служебные `_report_*`/`_check_*`/
`_typical_comments.md`). Формат: `docs/annotation_specification.md`; эталоны
стиля: `annotations/page_002.md`, `page_007.md`, `page_010.md`.

Публикация черновиков (проверенная процедура — deployment-log, 2026-07-10):
конвертация md→JSON (`scripts/annotation_converter.py`) → бэкап БД → на проде
`scripts/api/import_annotations.py <dir> --dry-run`, затем боевой (импорт
аддитивный: существующие id пропускает, ничего не удаляет) → `docker restart
redpen-api-1` (publish_all на старте) → curl-проверки → рендер скопировать в
локальный клон `redpen-publish`, commit+push. Поля `tags`/`confidence` из md
в модель данных пока не переносятся.

## Рабочие процедуры

- **Тесты**: `pytest` в корне (быстрые, без браузера; ~209+). JS — `node --check`
  + ручные сценарии из agent-instructions.
- **Сборка сайта**: `python scripts/build_website.py --skip-tests --skip-push
  [--target-dir ./out]`. Конвертация md→json аннотаций по умолчанию ВЫКЛЮЧЕНА
  (канон — БД); включается только `--annotations-from-md`.
- **Деплой контента**: push в `redpen-publish` → на сервере
  `docker restart redpen-content-sync-1`.
- **Деплой бэкенда/инфры**: scp изменённых файлов в
  `root@70.34.202.231:/root/apps/redpen/infra` → `docker compose up -d --build
  <svc>`. Это НЕ git-клон — детали топологии в памяти `redpen-deployment-model`
  и deployment-log (2026-07-09: bind-mount `redpen-publish` там — заглушка).
- **Прод трогать только с явного подтверждения пользователя.** Перед миграциями
  данных — именной бэкап БД (`VACUUM INTO`); ежедневный бэкап уже есть в cron.
- Многошаговую работу вести с журналом `docs/stage-N-progress-log.md`; каждый
  деплой — запись в `docs/deployment-log.md`.
- Секреты — только в env/`.env.secrets` на сервере, в git им не место.
