# RedPen — контекст проекта для агента

RedPen публикует постраничный критический разбор школьных учебников истории
(Мединский/Торкунов): поверх изображений страниц — кружки-замечания с фактчеком,
разбором манипуляций и умолчаний. Прод: https://medinsky.net (сайт) +
https://api.medinsky.net (API редактирования). Книг в системе две:
`medinsky11klass` (11 класс, 1945—2020-е; разбор идёт) и `medinsky10klass`
(10 класс, 1914—1945; заведён 2026-08-21, замечаний пока нет).

## Главный инвариант — сайт полностью статический

Опубликованный сайт — самодостаточный набор файлов: раздаётся любой статикой,
копируется на флешку, работает офлайн. **Просмотрщик никогда не обращается к
API** — замечания/текст/картинки только из статических файлов по относительным
путям. API и БД обслуживают исключительно редактор (`/app/`) и кабинет
(`/cabinet/`). Любая доработка, дающая просмотрщику сетевую зависимость, не
принимается. Подробнее: `docs/README.md`, раздел «Ключевое ограничение».

## Три репозитория (независимые, без submodules)

- **этот** (`redpen-infra`) — скрипты, шаблоны фронтенда, API, тесты, доки;
- `redpen-content/` (рядом или внутри) — исходники: картинки, текст,
  markdown-замечания, черновики;
- `redpen-publish/` — собранный статический сайт (он же офлайн-артефакт;
  push сюда = публикация контента).

## Как устроено (после этапов 0–3, июль 2026)

```
Редактор/кабинет ──▶ API (FastAPI, scripts/api/) ──▶ SQLite (канон:
                       auth: Google GIS + роли        remarks + history +
                       viewer/editor/admin, CSRF      users/sessions, том redpen_db)
                                │
                                └─▶ publisher.py: на каждую мутацию рендерит
                                    «голый» JSON-массив remarks/page_NNN.json
                                    И перерисовывает pages/<label>/index.html
                                    в томе redpen_public. Оба шага обязательны:
                                    просмотрщик читает не JSON, а инлайновый
                                    блок redpen-page-data внутри HTML
content-sync: публикует статику из git redpen-publish, НО каталоги */remarks/
исключены (их владелец — API); замечания в git-снапшот попадают обратной
синхронизацией рендера (см. deployment-log, запись 2026-07-10).
```

Ключевые факты, на которых легко ошибиться:
- формат опубликованных замечаний — «голый» массив
  `[{id,text,kind,coords,tags}]`; `serverPageSha` и статусы живут только в API/БД;
- **черновики лежат в том же `page_NNN.json`**, помечены `"draft": true` и тегом
  `draft`; просмотрщик скрывает их по умолчанию и раскрывает по URL-параметру
  (`?tags=`/`?notags=`, легаси `?showDrafts=1`). В анонимные ответы API черновики
  по-прежнему не попадают. Формат и семантика фильтра —
  `docs/remark_specification.md`;
- теги — таблица `remark_tags`; имена `draft`/`published`/`deleted`
  зарезервированы (тег `draft` производный, канон — колонка `status`);
  отсутствие `tags` в запросе = «не трогать», `[]` = «очистить»;
- `compute_page_sha` считается по `render_page()` (без тегов и черновиков) —
  не расширять, это вход оптимистической блокировки редактора; **он же намеренно
  заморожен в именах, действовавших до переименования сущности** (`annType`,
  `main`/`comment`): сдвиг хеша выдал бы 409 всем открытым сессиям редактора,
  а наружу этот массив не отдаётся;
- id замечаний уникальны в пределах страницы, не глобально;
- ключ страницы — файловый (`"006"`, `"000"`, `"-01"`), в БД `page_num` TEXT;
- нумерация для читателя — по манифесту `pages[{file,label}]` в metadata.json
  (`?p=A1`, `?p=17`); легаси `?page=N` работает всегда (см.
  `docs/page-addressing-proposal.md`);
- API-контейнер работает под uid 10001 — права на томах выдаются явно
  (грабли описаны в памяти и deployment-log).

## Сущность называется «замечание» (remark)

С 2026-08-29 сквозной термин проекта — **замечание** / `remark`. До этого одна и
та же вещь называлась тремя способами: `annotation` в БД и API, `comment` в
читательском интерфейсе (и заодно как значение поля), «замечание» — только в
пояснительных текстах на титульной.

Что как называется теперь:

| было | стало |
|---|---|
| таблицы `annotations` / `annotation_tags` / `annotation_history` | `remarks` / `remark_tags` / `remark_history` |
| колонки `ann_id` / `ann_type` | `remark_id` / `kind` |
| значения `main` / `comment` | `major` / `minor` |
| ключи JSON `annId` / `annType` | `remarkId` / `kind` |
| `GET /api/annotations` | `GET /api/remarks` |
| каталоги `<doc>/annotations/`, `annotations_draft/` | `remarks/`, `remarks_draft/` |
| ключ md-меты `type:` | `kind:` |
| `_typical_comments.md` | `_typical_remarks.md` |
| CSS `.comment-popup` / `.comment-content` / `#global-comment*` | `.remark-popup` / `.remark-content` / `#remark-sidebar`, `#remark-body` |

**Не переименовано намеренно:** `.circle` и `circle-<id>` (нейтральная
геометрия), инлайновый блок `redpen-page-data`, имена файлов `page_NNN.json`,
ключи `id`/`text`/`coords`/`tags`/`category`/`status`/`draft`, `serverPageSha`,
пути `/api/editor/...`, URL-параметры, модуль `scripts/annotation_categories.py`
(он про категории приёмов, а не про замечания).

**Фаза 6 снята 2026-08-30, выложена в тот же день** (deployment-log). Убраны: приём
`annType`/`annId` и старых значений в API, дублирующая выдача обоих наборов
ключей, алиасы `/api/annotations*`, дублирующая запись файлов в
`<doc>/annotations/` вместе с четырьмя `--exclude` в content-sync (первый
прогон после выкладки уносит каталог с тома — это и есть уборка), второй ключ
`annType` в `redpen-page-data`. В nginx добавлен постоянный 301 со старых
JSON-адресов.

**Навсегда** остаются толерантными к прежним именам:
- регексп путей в `scripts/analytics.py` — исторические access-логи неизменяемы;
- `db.normalize_snapshot()` — старые ревизии остаются в журнале;
- приём старых значений в `db.upsert_remark_db` и `scripts/remark_kinds.py`
  (единый источник таблицы `LEGACY_KINDS`, до 2026-08-30 копировавшейся в
  четырёх местах) — markdown-черновики писались годами;
- фолбэк `kind || annType` в `templates/js/redpen-markers.js`: страницы
  перерисовываются по одной, а розданные офлайн-копии не перерисуются никогда;
- **`render_page()` и `publisher.legacy_kind()`** — заморожены в именах
  `annType`/`main`/`comment`. Это вход `compute_page_sha`, то есть
  оптимистической блокировки: сдвиг хеша выдал бы 409 всем открытым сессиям
  редактора. Наружу этот массив не отдаётся. Проверено при снятии фазы 6: хеши
  всех 84 страниц с опубликованными замечаниями не изменились.

Миграция базы — `db._rename_legacy_to_remarks()`, вызывается из `init_db()`
**строго до** `executescript`: иначе `CREATE TABLE IF NOT EXISTS remarks` создаст
пустышку и переименование упадёт. Тесты — `tests/test_remark_rename.py`.
Датированные журналы (`deployment-log.md`, `stage-N-progress-log.md` и прочие)
намеренно не переписаны: правка сделала бы записи о прошлом ложными.

## Вторая книга — 10 класс (`medinsky10klass`)

Заведена 2026-08-21 из `medinskij_torkunov_istorija_rossii_10_kl_bazovyj_2023.pdf`
(497 стр., «История России. 1914—1945 годы», часть 1). Конвейер тот же, отличий нет:
- нарезка страниц — `pdftoppm -png -r 144`, файлы `images/page_NNN.png`, где
  **NNN = номер страницы PDF минус 1**, то есть NNN совпадает с печатным номером
  (обложка `000`, титул `001`, выходные данные `002`, печатные 003—496);
- текст — `scripts/extract_text.py`, файлы `text/page_NNN.json` **со сдвигом +1**
  (как в 11 классе): `text/page_007.json` = `images/page_006.png` = печатная стр. 6;
- `paragraphs_list.txt` собран по оглавлению и сверен постранично: 40 § в трёх
  главах (§ 11—12, 22—23, 25—26, 37—38, 39—40 — сдвоенные), плюс аппарат глав;
  хвост книги (Заключение, словарь, хронология, списки) — руками в `meta.json`;
- `images_with_grid/` сгенерированы на все 497 страниц (в git не коммитятся —
  как и у 11 класса, они восстановимы `scripts/make_grid_images.py`).

Запускать агента-аннотатора здесь нужно с явным `--doc-id`:
`python3 scripts/make_agent_prompt.py <номер> --doc-id medinsky10klass -o <файл>`
(без флага скрипт по-прежнему берёт 11 класс). Эталоны стиля и реестр
`_typical_remarks.md` — общие для обеих книг, лежат в каталоге 11 класса; шаблон
задания теперь ссылается на них абсолютным путём.

**Выложена на прод 2026-08-22** (deployment-log): сайт (карточка на титульной
в состоянии «разбор ещё готовится», все 497 страниц noindex — замечаний нет)
и 52 параграфа в таблице `sections`. **Не сделано:** ни одного замечания; свод правил
агента переписан до v4 (2026-08-22): «Рамка эпохи» разделена на общую часть и
подразделы по книгам, зашитые пути 11 класса разведены на `<docId>`. Реестр
типовых замечаний и эталоны стиля остаются общими и лежат у 11 класса.

Что показал корпус при подготовке (пригодится при разборе): эта книга
**разговорчивее** 11 класса. ГУЛАГ, репрессии, раскулачивание, депортации,
голод 1932—1933, секретный протокол, Власов — всё названо, кое-что отдельными
подразделами; ноль дают только ярлыки («голодомор», «Большой террор»,
«заградотряд»). Поэтому «в учебнике не сказано» здесь почти всегда ошибка,
а работа — в разборе обезвреженных признаний.

## Контент-конвейер и агент-аннотатор

Замечания пишет **агент-аннотатор** по промпту `docs/remark-agent-prompt.md`
(это главный «субагентский» промпт проекта, поддерживай его актуальность):
один запуск = один параграф из `redpen-content/<docId>/paragraphs_list.txt`;
перед запуском нужны картинки с сеткой (`python3 scripts/make_grid_images.py`).
Задание **не пишется руками** — генерируется из шаблона:
`python3 scripts/make_agent_prompt.py <номер> -o <файл>` (шаблон —
`docs/remark-agent-run-prompt.template.md`, пути контейнерные `/work`).
Рукописные сжатые задания теряют правила: так §20 вышел без единой ссылки в телах
замечаний (2026-08-08).
Агент смотрит `images_with_grid/`, цитирует по `text/*.json` (внимание: сдвиг
нумерации текстовых файлов +1), обязан выполнять «протокол умолчаний» (grep по
всему корпусу текста перед любым «в учебнике не сказано») и верифицировать
источники. Результат — черновики в `redpen-content/<docId>/remarks_draft/`
(`page_NNN.md` в формате `~~~meta` + служебные `_report_*`/`_check_*`/
`_typical_remarks.md`). Формат: `docs/remark_specification.md`; эталоны
стиля: `remarks/page_002.md`, `page_007.md`, `page_010.md`.

Публикация черновиков (проверенная процедура — deployment-log, 2026-07-10):
конвертация md→JSON (`scripts/remark_converter.py`) → бэкап БД → на проде
`scripts/api/import_remarks.py <dir> --dry-run`, затем боевой (импорт
аддитивный: существующие id пропускает, ничего не удаляет) → `docker restart
redpen-api-1` (publish_all на старте) → curl-проверки → рендер скопировать в
локальный клон `redpen-publish`, commit+push. Поля `tags`/`confidence` из md
конвертер теперь выносит в `tags` (`confidence: high` → тег `confidence:high`),
импортёр кладёт их в БД. Для уже импортированных замечаний теги подтягиваются
скриптом `scripts/api/backfill_tags.py <md_dir> --doc <docId>` (по умолчанию
только отчёт, запись — `--apply`).

## Рабочие процедуры

- **Тесты**: `pytest` в корне (быстрые, без браузера; 693 на 2026-08-31).
  JS — `node --check`. Браузерные сценарии — `tests/manual/` (маркеры у
  читателя, приёмка редактора на локальном стенде), см. `tests/README.md`.
- **Сборка сайта**: `python scripts/build_website.py --skip-push
  [--target-dir ./out]`. Конвертация md→json замечаний по умолчанию ВЫКЛЮЧЕНА
  (канон — БД); включается только `--remarks-from-md`. Флаг `--skip-tests`
  принимается, но с 2026-08-30 ничего не выключает: браузерные проверки,
  которые сборка гоняла, целились в снесённый SPA.
- **Деплой контента**: push в `redpen-publish` → на сервере
  `docker restart redpen-content-sync-1`.
- **Деплой бэкенда/инфры**: scp изменённых файлов в
  `root@70.34.202.231:/root/apps/redpen/infra` → `docker compose up -d --build
  <svc>`. Это НЕ git-клон — детали топологии в памяти `redpen-deployment-model`
  и deployment-log (2026-07-09: bind-mount `redpen-publish` там — заглушка).
- **Прод трогать только с явного подтверждения пользователя.** Перед миграциями
  данных — именной бэкап БД (`VACUUM INTO`); ежедневный бэкап уже есть в cron.
- Многошаговую работу вести с журналом `docs/stage-N-progress-log.md`; каждый
  деплой — запись в `docs/deployment-log.md`.
- Секреты — только в env/`.env.secrets` на сервере, в git им не место.

## Состояние работ (на 2026-08-30)

- **Переименование сущности в «замечание» (remark) — на проде**
  (deployment-log, 2026-08-29). Три выкладки: исключения rsync/nginx →
  статика → API с миграцией базы. Счётчики после миграции сошлись с
  замерами до неё строка в строку, `compute_page_sha` не сдвинулся ни на
  одной из 315 страниц. Переходная совместимость снята фазой 6 (2026-08-30,
  локально) — см. раздел «Сущность называется „замечание“» выше.
- **Этап 4, фаза 1 — на проде** (deployment-log, 2026-08-21). Выложены:
  цветовая классификация по семи категориям, `category_source` («разобрано или
  нет» — `other` больше не значит две разные вещи), параграфы (`sections`, 42 из
  манифеста), журнал ревизий (`rev_no`/`parent_rev_id`/`agent_run_id`/`summary`
  плюс три индекса, которых не было), `agent_runs`, `?only=<id>` — постоянная
  ссылка на одно замечание, кабинет на приглашениях.
- **Анонимность — нормативный документ `docs/anonymity-model.md`.** Система
  хранит о человеке только `HMAC(IDENTITY_PEPPER, google_sub)` и выбранный им
  псевдоним; email/имя/аватар не читаются из токена вовсе. Доступ — одноразовыми
  приглашениями, `editor_allowlist` и `ADMIN_EMAILS` упразднены. Миграция
  проведена на проде: остаток личных данных — 0 строк.
- **Публикация доезжает до читателя.** Просмотрщик читает не JSON, а инлайновый
  блок внутри HTML, поэтому `publisher` перерисовывает и страницу. Каталог
  `<doc>/pages/` теперь принадлежит API (uid 10001), владение восстанавливает
  `content-sync/entrypoint.sh` — правка в `content_sync.py` бесполезна, тот
  путь мёртв.
- **Кроны на проде**: ежедневный бэкап БД (был сломан с 2026-07-09, починен),
  ночной снапшот тома в git в 00:00 и почасовая аналитика (`redpen-stats`).
- **Аналитика — на проде с 2026-08-23** (deployment-log). Счётчика на сайте нет:
  разбирается access-лог Caddy. Посещаемость считает Matomo (`stats.medinsky.net`
  под паролем Caddy плюс собственный вход); параграф подставляется в адрес
  при импорте, поэтому отчёт даёт «книга → § → страница». Спрос против покрытия,
  `?only=` и легаси-адреса — `scripts/ops/redpen_stats.py report`.
- **Опрос замечаний (`/survey/`) — на проде** (deployment-log, 2026-08-31).
  Голос из-за пределов закрытого
  круга: человек называет псевдоним, получает до десяти случайных замечаний
  из пула (`rating_pool`, ведёт админ из кабинета) и отвечает по трём шкалам.
  Респондент **не заводится в `users`** — свои таблицы `survey_respondents`
  и `survey_ratings`, подпись `anonymous:<псевдоним>` собирается на чтении,
  опознание — заголовком `X-Survey-Token`, а не кукой. Шкала `admissibility`
  стала бинарной («можно ли публиковать в текущем виде»: 1 нет / 2 да),
  диапазон переехал из модуля в шкалу. Ответы видны в ленте замечания
  (`source: "survey"`) и в таблице результатов; в статику не попадают никогда.
  Нормативная часть — `docs/anonymity-model.md`, раздел «Анонимные
  респонденты опроса». **Пулом с 2026-08-31 ведает редактор, а не админ**
  (сводка результатов осталась админской), и членство в пуле видно в самом
  замечании: `GET /api/remarks` и карточка отдают `inPool`/`poolAnswers`,
  есть фильтр `?inPool=true|false`. Проставляет их отдельный шаг чтения
  `db._attach_pool`, который публикация не вызывает, — в статику пул не течёт.
- **Действия, оценки и комментарии — на проде** (выехали 2026-08-30 вместе
  с общей уборкой; пользовался ими до 2026-08-31 никто — `remark_ratings` и
  `remark_notes` были пусты). Тип действия стал явной сущностью:
  колонка `remark_history.changes` (JSON-массив токенов словаря
  `scripts/api/remark_actions.py`) отвечает на вопрос «что изменилось», а
  `action` остался ответом на «как это записано». Появились узкие
  `PATCH .../status|category|tags`, оценки по трём шкалам
  (`remark_ratings`, шкалы в `scripts/api/rating_scales.py`: интересность
  факта / важность / допустимость) и тред рабочих комментариев
  (`remark_notes`, один уровень ответов). **Оценки и комментарии в статику не
  попадают никогда** и ревизиями не являются — сводятся только на чтении, в
  `GET /api/remarks/.../timeline`. Старые ревизии заполняет
  `scripts/api/backfill_history_changes.py` (`--apply`), а не старт API.

## Карта документации (docs/)

**Живое** — обязано быть верным, правится вместе с кодом:
- `README.md` — обзор репозитория, раскладка данных, конвейер, статическое
  ограничение (сюда влит бывший `PROJECT_STRUCTURE.md`);
- `STATE_OVERVIEW.md` — карта «какой адрес что отдаёт, каким кодом, откуда
  данные» и список того, что важно не сломать;
- `anonymity-model.md` — **нормативный**: что система хранит о людях и почему;
  ослабление схемы начинается с правки этого документа, а не кода;
- `remark_specification.md` — формат замечаний, теги, действия, оценки, опрос;
  `REMARK_IDS.md` — id элементов в DOM;
- `analytics-setup.md` — установка Matomo и сбора счётчиков (вынесено из
  исторического `server-setup-guide.md`, где успело разойтись с кодом);
- `local-docker-agent.md` — запуск агентов в локальном docker.

**Промпты агентов** — живые, поддерживать актуальными:

  проекта. `remark-agent-run-prompt.template.md` — шаблон задания
