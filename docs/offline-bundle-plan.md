# План: офлайн-архив разбора (скачиваемая копия сайта)

Статус на 2026-08-15: шаг 1 сделан и проверен локально на настоящем контенте
(см. «Что уже готово»); на прод ничего не выкладывалось.

## 0. Что было не так с обещанием на главной

Старый текст: «Здесь нет ни регистрации, ни счётчиков, ни **обращений к нашему
серверу при чтении**: … Копию сайта можно скачать целиком, положить на флешку и
читать без интернета».

Два дефекта:

1. **«Нет обращений к серверу» — неверно буквально.** Чтение сайта — это и есть
   обращения к серверу: страница, css/js, `images/<page>.png`, `text/<page>.json`,
   `annotations/<page>.json`. Правда, которую хотели сказать: нет регистрации,
   счётчиков, аналитики и обращений к **редакторскому API**. Плюс сейчас есть
   и настоящее нарушение — `templates/document_index.html:144` тянет
   `marked.min.js` со **стороннего CDN jsdelivr**, то есть при каждом чтении
   IP читателя утекает третьей стороне, а офлайн разметка аннотаций деградирует
   до fallback-форматирования.
2. **«Копию можно скачать» — не подтверждено ничем.** Скачать нечего: архива нет,
   а простое «сохранить страницу» книгу не соберёт.

Шаг 0 (сделан): текст переписан в `scripts/build_website.py` — обещание
скачивания заменено на «архив готовим», остальное сформулировано проверяемо.

**Блокер перед выкладкой нового текста:** vendor'ить `marked.min.js` в
`templates/js/vendor/marked.min.js` и убрать тег jsdelivr. Иначе фраза «ничего
больше никуда не отправляет» остаётся ложной. Работы — 15 минут, но это
скачивание внешнего файла в репозиторий: делаем по явному подтверждению.

## 1. Как это ложится на нашу модель URL

Модель адресации сейчас: `<docId>/index.html?p=<метка>` (легаси `?page=N`),
фильтры `?tags=`/`?notags=`, флаг `?editor=1`. Разбор — целиком на клиенте
(`templates/js/main.js`), сервер никаких rewrite не делает: nginx отдаёт статику
как есть. Проверено: **абсолютных путей в шаблонах нет** — только относительные
(`../css/`, `../js/`, `images/…`, `annotations/…`).

Следствия для офлайн-копии:

- Каталог книги можно положить куда угодно; адрес
  `file:///Volumes/USB/redpen/medinsky11klass/index.html?p=17` работает точно так
  же, как на сайте. Query-строка на `file://` разрешена и доходит до JS.
- Кнопка ⌂ ведёт на `../index.html` — значит корень бандла обязан содержать
  свой index.
- **Единственный настоящий блокер — `fetch()` на `file://`.** Origin у
  `file://`-страницы — `null`, и Chrome/Firefox блокируют любой `fetch` к
  соседним файлам. `<img src>` при этом работает. У просмотрщика ровно четыре
  точки загрузки данных:
  - `main.js:279` — `metadata.json`
  - `main.js:411` — `annotations/<id>.json`
  - `main.js:422` — `annotations/<id>.drafts.json` (легаси, в бандл не нужен)
  - `annotations.js:70` — `text/<id>.json`

  Их и надо обойти.

## 2. Решение: данные бандла грузятся скриптом, а не fetch'ем

В бандл кладётся `offline-data.js` — один файл вида

```js
window.REDPEN_OFFLINE = JSON.parse("{\"metadata\":{…},\"annotations\":{\"006\":[…]},\"text\":{\"006\":{…}}}");
```

(JSON.parse из строкового литерала, а не JS-литерал объекта: парсится заметно
быстрее). Объём для `medinsky11klass` — аннотации 2.6 МБ + текст 3.4 МБ ≈ 6 МБ
на фоне 192 МБ картинок, то есть несущественно. Если старт окажется заметно
медленным — запасной вариант — грузить по странице (`offline/text/006.js`,
инъекция `<script>` по требованию); закладываться на него сразу не стоит.

Плюс новый файл `templates/js/redpen-offline.js`:

- если `window.REDPEN_OFFLINE` не определён — **no-op** (на сайте он ничего не
  делает и ничего не ломает);
- иначе патчит `window.fetch`: запросы, чей путь совпадает с
  `metadata.json`, `annotations/<id>.json`, `text/<id>.json`, отдаются
  синтетическим `Response` из `REDPEN_OFFLINE`; всё остальное — сквозняком.

Так `main.js` и `annotations.js` **не меняются вовсе** — это главный аргумент за
патч `fetch` вместо ввода общего хелпера в четырёх местах.

Из index.html книги в бандле сборщик дополнительно **вырезает три редакторских
скрипта** (`redpen-editor-panel.js`, `redpen-auth.js`,
`redpen-editor-bootstrap.js`) и блок с `REDPEN_API_BASE`. Тогда офлайн-копия
физически не содержит кода, способного обратиться к api.medinsky.net, — и это
проверяется грепом по архиву, то есть обещание становится верифицируемым.

Черновики (`draft`) в бандле остаются ровно как на сайте — по умолчанию скрыты,
раскрываются `?tags=draft`. Бандл = копия сайта, а не отдельная выборка.

## 3. Состав архива (одна книга)

```
redpen-medinsky11klass-offline.zip
└─ redpen-medinsky11klass/
   ├─ ЧИТАТЬ.html          → мета-редирект на medinsky11klass/index.html
   ├─ README.txt           → как открыть, что внутри, дата сборки, версия
   ├─ index.html           → простой корневой экран с одной карточкой книги
   ├─ favicon.svg
   ├─ css/  js/            → копия статики сайта + js/redpen-offline.js
   └─ medinsky11klass/
      ├─ index.html        (без редакторских скриптов, со ссылкой на offline-data.js)
      ├─ offline-data.js
      ├─ metadata.json     (оставляем — пригодится, если открывать через локальный сервер)
      ├─ cover.png
      ├─ images/  text/  annotations/
```

Корневой `index.html` бандла генерируется отдельным мини-шаблоном, а не копируется
с сайта: сайтовый селектор ссылается на другие книги, которых в архиве нет.

Размер: ~198 МБ, из них 192 МБ — PNG страниц. Zip их почти не жмёт, поэтому
`images/` кладём методом `ZIP_STORED` (быстрее пакуется и распаковывается),
остальное — `ZIP_DEFLATED`. Итог ≈ 195 МБ.

## 4. Сборка

Новый скрипт `scripts/make_offline_bundle.py`:

```
python3 scripts/make_offline_bundle.py --doc medinsky11klass \
    --site-dir /srv/public --out /srv/downloads/redpen-medinsky11klass-offline.zip
```

Шаги: копия статики во временный каталог → сборка `offline-data.js` из
`annotations/*.json` + `text/*.json` + `metadata.json` → правка index.html книги →
генерация корневого index/README → zip → рядом манифест
`*.zip.json` (`{size, sha256, builtAt, doc, pages, annotations}`).

Тесты (pytest, без браузера): собрать бандл на фикстуре из 2–3 страниц и
проверить, что в архиве нет строк `api.medinsky.net`, `cdn.jsdelivr.net`,
`accounts.google.com`; что `offline-data.js` содержит все страницы из
manifest'а; что все `src`/`href` в html относительные.

## 5. Где это живёт на проде

Ключевое ограничение: **архив нельзя класть в git `redpen-publish`** (200 МБ,
лимит GitHub на файл — 100 МБ, история распухнет). Значит, он собирается на
сервере.

- Новый том `redpen_downloads`.
- `frontend` монтирует его в `/usr/share/nginx/html/downloads:ro` → URL
  `https://medinsky.net/downloads/redpen-medinsky11klass-offline.zip`.
  Caddy править не нужно: всё, кроме `/.hooks/*`, и так уходит на frontend.
- **Проверить перед реализацией:** не удаляет ли `content-sync` неизвестные
  каталоги в `/srv/public` (если публикация идёт `rsync --delete`, `downloads/`
  надо либо занести в исключения, либо монтировать отдельным путём, а не внутрь
  `redpen_public`).
- Сборщик — одноразовый сервис `offline-builder` в compose (профиль, чтобы не
  поднимался постоянно): `docker compose run --rm offline-builder`. Ему нужны
  `redpen_public:ro` и `redpen_downloads:rw`. Запуск — вручную после значимых
  выкладок и еженедельно по cron; чаще смысла нет.
- Место на диске: временный каталог + архив ≈ 400 МБ пиково. Проверить `df`
  перед первым прогоном.

## 6. Ссылка на сайте

После первой удачной сборки в блоке «Этот сайт можно унести с собой» вместо
«архив готовим» — ссылка с честными данными: имя файла, размер, дата сборки,
sha256 (в `<details>`), и одной строкой «распакуйте и откройте `ЧИТАТЬ.html`».
Цифры берём из манифеста и вписываем в `build_website.py` при сборке сайта
(не fetch'ем на клиенте — просмотрщик остаётся без сетевых зависимостей).

## 7. Приёмка — обязательная, раз мы это обещаем

Пока не пройдено, ссылку на сайте не публикуем:

1. Скачать архив с прода по публичному URL (не с диска сервера).
2. Распаковать в чистый каталог, **отключить сеть**.
3. Открыть `ЧИТАТЬ.html` в Chrome и Safari: обложка, листание, `?p=17`,
   кружки-аннотации, попапы, общий комментарий, разметка в аннотациях
   (это и есть тест на vendor'енный marked), мобильная ширина.
4. В консоли — ноль ошибок; во вкладке Network — ни одного запроса за пределы
   `file://`.
5. `grep -R "medinsky.net\|jsdelivr\|google" распакованный_каталог` — пусто
   (кроме текстов аннотаций и README).

## 10. Осознанно отложено

- **Лёгкий архив (~30–50 МБ).** Картинки в WebP/JPEG вместо PNG. Требует, чтобы
  `main.js` знал расширение (например, поле `imageExt` в metadata) — то есть
  правка просмотрщика, поэтому отдельной задачей.
- **Несколько книг в одном архиве.** Структура бандла уже это допускает
  (корневой index + несколько каталогов книг); пока книга одна, не усложняем.
- **PDF/EPUB-версия разбора** — другой продукт, не «копия сайта».
