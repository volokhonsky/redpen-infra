# Постраничные адреса и индексируемость — журнал работ

Только дописывать. Постановка и решения — в утверждённом плане; здесь ход работ,
замеры и то, что осталось.

## Зачем

У сайта была нулевая видимость для поиска. Замер до работ: если вырезать из
`redpen-publish/medinsky11klass/index.html` скрипты и теги, остаётся **159
символов** текста на весь корпус из 1257 аннотаций — и среди них «Загрузка...».
Вся книга жила по одному адресу, аннотации подтягивались JS из JSON. Ни
`sitemap.xml`, ни `robots.txt`, ни одного `og:`/`canonical` во всём репозитории.

## Сделано (2026-08-16)

### Данные для заголовков

- `scripts/chapters.py` — новый модуль: собирает `chapters` в
  `metadata.json` из `redpen-content/<doc>/paragraphs_list.txt`.
  Рукописный `chapters` в `meta.json` **потерял §10–§23** — около 170 страниц
  не попадали ни в одну секцию. Теперь у секций есть и `startPage`, и
  `endPage`, поэтому «страница → §» считается точно, а не угадывается как
  «последняя секция с `startPage ≤ N`».
- Главы, которых нет в оглавлении (Приложения, Указатель), сохраняются из
  прежнего `metadata.json`; границы достраиваются от соседей.
- Проверено: все печатные страницы 3–447 попадают в главу; без секции
  остаются только те, у кого её и нет (Введение, шмуцтитулы, Указатель).

### Постраничный HTML

- `scripts/page_html.py` — рендерит `<doc>/pages/<метка>/index.html` для всех
  448 страниц плюс оглавление документа `<doc>/index.html`.
- Два представления в одном файле:
  - **опубликованные** аннотации — настоящим текстом в панели (это
    индексируется);
  - **все**, включая черновики, — в инлайновом
    `<script type="application/json" id="redpen-page-data">`. Содержимое
    `<script>` не индексируется как текст страницы, но доступно JS сразу, без
    единого запроса. Так `?showDrafts=1` работает, а невычитанные черновики в
    индекс не попадают.
- В блобе лежит уже отрендеренный HTML, а не markdown, — зависимость от
  `marked` с CDN новым страницам не нужна.
- `<meta name="robots" content="noindex,follow">` на страницах без
  опубликованных аннотаций: адрес работает, но тонкая страница не индексируется.
- Markdown рендерится переиспользованным `blog.render_markdown`. Добавлена
  нормализация сырого `<a href>` в markdown-ссылку: две аннотации в корпусе
  (`page_002`, `page_004`) предшествуют правилу «только markdown» и иначе
  показали бы литеральные теги.

### Просмотрщик

- `templates/js/page-view.js` — новый самодостаточный скрипт страницы.
  Намеренно **не** переиспользует `main.js`/`annotations.js`: те написаны под
  SPA-переключение страниц, которого здесь больше нет.
- `templates/css/page-panel.css` — стили панели, оглавления и раскладки.
  `responsive.css` новым страницам не подключается: он весь про
  `#global-comment-container` и войну `!important`.
- `templates/js/legacy-page-redirect.js` — старые `?p=`/`?page=`/`#pageN`
  уводят на новый адрес с переносом фильтров тегов.
- SPA остаётся на `<doc>/document_index.html` как точка входа редактора и
  помечен `noindex,follow`, чтобы не конкурировать за индексацию.

### Прочее SEO

- `scripts/sitemap.py` — `sitemap.xml` и `robots.txt`. Карта строится
  **сканированием собранного сайта** и пропускает всё с `noindex`, поэтому не
  может разъехаться с реальностью.
- `canonical` + Open Graph на страницах разбора, оглавлении, лендинге и в блоге.

## Возврат поп-апов и переезд списка вниз (2026-08-16, тот же день)

При переводе на постраничные адреса в `page-view.js` была перенесена только
подсветка «пункт ↔ кружок», а **поп-ап при наведении не перенесён вовсе** —
основная механика сайта пропала (`.comment-popup` в DOM: 0). Исправлено.

- Механика воспроизведена из `comment-content.js`/`annotations.js` без
  SPA-глобалов: наведение показывает, клик закрепляет, клик мимо закрывает.
  Сохранены все тонкости, без которых поп-ап «убегает» из-под курсора:
  три флага (`hoverShown`/`clickShown`/`popupHover`), **задержка 50 мс** при
  уходе с маркера, ширина 60 % от скана для длинных (>600 символов) и
  картиночных комментариев, выбор стороны «сверху/снизу» с зазорами 10/20 px.
- Распорка под поп-апом у нижнего края кладётся **только в `body`**: внутри
  `#layout` элемент `width:100%` схлопывает соседа по флексу и картинка
  исчезает. Проверено: ширина скана 919 px до и после, высота документа растёт
  1506 → 1660, распорка убирается при скрытии.
- Список комментариев переехал из правой колонки **под скан**, во всю ширину
  (`max-width: 60rem`). Правой колонкой он отбирал ширину у страницы и
  дублировал то, что и так показывает поп-ап.
- На тач-устройствах список свёрнут в `<details>` «Все комментарии (N)».
  В разметку он приходит с `open`, сворачивает его JS — поэтому краулер и
  читатель без JS видят полный текст. Высота страницы на телефоне
  **4088 → 975 px**.
- Индексируемый слой не пострадал: 86 страниц, 172 844 символа.

Отдельная грабля, всплывшая дважды: **сворачивание и подсветку нельзя вешать на
ширину экрана**. Пока вкладка не отрисована, `innerWidth` равен нулю,
медиазапрос по ширине ложно срабатывает как «мобильный», и на десктопе молча
пропадала то подсветка, то список. И JS, и CSS теперь опираются на наличие
курсора (`(hover: hover) and (pointer: fine)` / `@media (hover: none)`).

## Отмена типа `general` — подготовлено, на прод не выкладывалось (2026-08-16)

Разбор всех 16 аннотаций показал: две из них не аннотации вовсе.

- **Удалить (2):** `page_017/srv-import-0df25036` — тестовый мусор «Это заготовка
  комментария. Бубубу.» (его исходник `annotations/page_017.md` — в старом
  формате `---`, без id, поэтому сервер и выдал ему `srv-import-*`);
  `page_001/ann-page2-1` — приветствие сайта, а не разбор. Титульный лист не даёт
  якоря, а лендинг уже говорит то же и сильнее.
- **Конвертировать (14):** у каждой нашёлся естественный якорь. Координаты сняты
  по `images_with_grid`, проверены на попадание в границы скана и на отсутствие
  наложений с соседними маркерами. Решение целиком — в
  `docs/general-migration-map.json` (с обоснованием якоря на каждую).

Соотношение типов: 9 `main`, 5 `comment`. Восемь из четырнадцати — черновики,
и они обязаны черновиками остаться.

**Что сделано локально:**

- `docs/general-migration-map.json` — карта миграции;
- `scripts/api/migrate_general_annotations.py` — применение (dry-run по
  умолчанию). Отказывается работать, если названная в карте строка уже не
  `general` или если в БД есть `general`, которого нет в карте: карта обязана
  быть исчерпывающей, иначе тип нельзя убрать из API. Статус и теги
  сохраняются, всё идёт через `upsert_annotation_db`/`soft_delete_annotation`,
  то есть попадает в `annotation_history` и откатывается из кабинета;
- репетиция на копии боевых данных (1257 аннотаций): 14 конвертированы,
  2 удалены мягко, повторный запуск заблокирован защитой;
- исходники в `redpen-content` синхронизированы (искал по `id:`, а не по номеру
  страницы — там известный сдвиг нумерации);
- тип убран из `ANNOTATION_TYPES`, конвертера (теперь `type: general` — громкая
  ошибка), редактора, кабинета, легенды лендинга и документации, включая оба
  промпта агентов;
- 345 тестов зелёные, из них 13 новых на сам скрипт миграции.

**Один найденный по дороге баг, который стоил бы прода:** первая версия скрипта
искала строки через `db.list_page_annotations()`, а он возвращает только
опубликованные. Восемь черновиков из четырнадцати просто не были бы найдены.
Поймал тест `test_draft_stays_a_draft`; теперь поиск идёт через
`list_annotations(ann_type='general')`.

**Осталось (порядок важен):** сначала миграция данных на проде (именной бэкап
`VACUUM INTO` → dry-run → `--apply`), и только потом выкладка ужесточённого API.
В обратном порядке редактор на 16 страницах будет получать 400. Открытые вкладки
редактора на этих страницах получат 409: `compute_page_sha` считается по
`render_page()`, а там появляются координаты.

## Грабли, на которые стоит смотреть

- **Сборка в чистый `--target-dir` не содержит `annotations/`** (их владелец —
  БД, `content_sync` исключает `/*/annotations/`). Тогда все страницы выходят
  пустыми и `noindex` — то есть сайт тихо де-индексируется. `page_html`
  печатает громкое предупреждение; перед сборкой в чужой каталог аннотации
  надо скопировать из клона `redpen-publish`.
- Признак «мобильного» для подсветки — `(hover: hover) and (pointer: fine)`, а
  **не** ширина экрана: при нулевой или ещё не устоявшейся вёрстке медиазапрос
  по ширине ложно срабатывает и подсветка молча отваливается на десктопе.
- `make_offline_bundle.rewrite_doc_index()` ищет якорь «первый скрипт с
  `../js/`» и падает без него — правки шаблонов ломают офлайн-сборку.
