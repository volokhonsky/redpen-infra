# Текущее состояние системы RedPen (обзор)

Этот документ фиксирует текущее состояние системы и расположение ключевых файлов: просмотр учебника с замечаниями, режим редактора, бэкенд (этапы 0–3 плана `editor-improvement-plan.md`: auth + роли, SQLite-канон замечаний, публикация статики, кабинет) и инфраструктура. Быстрый вход в проект — корневой `CLAUDE.md`.

## Где что отдаётся (проверено на проде 2026-08-21)

| Адрес | Что это | JS |
|---|---|---|
| `<doc>/index.html` | оглавление книги (`page_html.render_toc`) | `legacy-page-redirect.js` |
| `<doc>/pages/<label>/index.html` | постраничный просмотрщик (основной путь читателя) | `page-view.js` |
| `<doc>/document_index.html` | старый SPA; **единственное место, где работает режим редактора** | `layout/comment-content/remarks/mobile/main` + редакторские |

Сборка пишет SPA в `<doc>/index.html` на шаге 3, а шаг 3.6 перезаписывает этот
файл оглавлением — поэтому SPA выживает только во второй копии. Планируется
снос SPA после переезда редактора в отдельное приложение:
`docs/refactoring-plan-2026-08.md`.

## Что делает система сейчас

- Просмотр учебника с замечаниями:
  - Рендер изображений страниц, кружков‑замечаний и всплывающих поп‑апов.
  - Навигация по страницам, включая поддержку параметра `?page=N` и обновление адресной строки при кликах по номерам страниц/Prev/Next (история браузера поддерживается через `pushState`).
  - Мобильный режим: отдельные оверлеи/навигация и показ замечаний.

- Режим редактора (включается `?editor=1` или глобальным флагом):
  - Справа вместо ленты замечаний монтируется панель редактирования.
  - Клик по пустому месту изображения задаёт координаты; клик по кружку подгружает черновик (тип, текст, координаты) и подсвечивает маркер.
  - Виды замечаний — только `major` и `minor`; координаты обязательны для обоих. Вид `general` (общее замечание страницы) упразднён миграцией 2026-08-16: конвертер отвергает его с ошибкой (`remark_converter.py`), в селекторе панели его нет (`redpen-editor-panel.js`). Остатки обработки `general` в `redpen-editor-bootstrap.js` — легаси для чтения старых черновиков.
  - Защита от потери несохранённых изменений:
    - При попытке уйти со «грязной» формы (клик по другому маркеру/пустому месту/смена типа) — спрашивается подтверждение; при отказе остаёмся в редактировании.
    - В режиме создания (new) смена координат по клику разрешена без подтверждения.
  - «Показать» и «Отправить»:
    - «Показать» — локально применяет изменения: создаёт/обновляет маркер, поп‑ап, поддерживает hover, синхронизирует baseline (форма становится «чистой»).
    - «Отправить» — реальный POST/PUT к `/api/editor/{docId}/{pageNum}[/{remarkId}]` (с сессией + CSRF-токеном); обрабатывает 401 (показывает вход), 403 с ролью viewer («недостаточно прав»), 403 CSRF (тихий ретрай с новым токеном), 409 (конфликт версий, предлагает перечитать страницу).

- Бэкенд API (этапы 0–2 из `docs/editor-improvement-plan.md` выполнены, в Docker):
  - FastAPI/Uvicorn; инбокс (`/api/store*`, файлы в `STORAGE_DIR`), редактор
    замечаний (`/api/editor/...`, включая `DELETE`).
  - Замечания — в SQLite (`db.py`, таблицы `remarks`/`remark_history`,
    канон); каждая мутация сразу рендерится и пишется в
    `<docId>/remarks/page_NNN.json` в `PUBLISH_DIR` (том `redpen_public`,
    его же раздаёт nginx) — правки редактора видны на сайте немедленно, без
    git-цикла. `POST /api/admin/publish-all` (и старт сервиса) перепубликует
    всё из БД — самолечение тома. CLI `import_remarks.py`/
    `export_remarks.py` переносят данные файлы⇄БД.
  - Аутентификация и роли — см. раздел «Аутентификация и роли» ниже.

- Кабинет `/cabinet/` (этап 3): рабочий экран для `editor`/`admin` — списки
  замечаний с фильтрами/поиском/пагинацией, публикация/снятие с публикации/
  удаление из таблицы, история изменений с откатом, админ-вкладка
  (allowlist, пользователи, «Перепубликовать всё», логи). Замечания могут
  быть черновиками (`status='draft'`) — видны только `editor`/`admin` (в
  кабинете и в editor-режиме основного просмотрщика, пунктирным маркером),
  никогда не попадают в статические JSON и анонимный/viewer-ответ API. См.
  раздел «Кабинет» ниже.

  - Поддержка `?page=N` (логическая страница) и обновление нумерации/адресной строки.

- `templates/js/remark-content.js`

- `templates/js/remarks.js`
  - Отрисовка кружков, пересчёт позиций, поведение hover/click (используется `main.js` и редактором).
- `templates/js/mobile.js`
  - Мобильные оверлеи/навигация, кнопки, показ замечания в мобильном режиме.
- `templates/js/redpen-editor-panel.js`
  - Панель редактора: вёрстка формы, методы `setDraft`/`getDraft`, валидация (тип/контент/coords), включение/отключение кнопок «Показать/Отправить/Отмена».
- `templates/js/redpen-editor-bootstrap.js`
  - Включение режима редактора по флагу; монтирование панели в правой колонке (`#global-comment-container`).
  - Делегированные клики: по изображению — заполнять coords, по маркеру — подгружать драфт и подсвечивать.
  - Хранение state (draft, baseline, editing mode), защита от потери изменений.
  - Локальный предпросмотр «Показать»: upsert маркера (класс `circle`, data‑атрибуты), обновление/создание поп‑апа с поддержкой hover, синхронизация baseline.
- `templates/document_index.html`
  - Старый SPA; сегодня публикуется только под этим именем и служит носителем режима редактора. Базовая страница просмотра: контейнеры `#image-container` (изображение/оверлеи), `#global-comment-container` (правая панель), верхняя пагинация; подключение JS.
- `templates/js/redpen-auth.js`
  - Общий клиент авторизации (`window.RedPenAuth`): CSRF-кэш, `me`/
    `loginWithToken`/`loginWithGoogle`/`logout`, загрузка Google Identity
    Services и рендер кнопки входа. Используется и редактором
    (`redpen-editor-bootstrap.js` делегирует сюда, с фолбэком на старую
    инлайн-реализацию, если файл не загружен), и кабинетом.
- `templates/cabinet/index.html`, `cabinet.js`, `cabinet.css`
  - Страница `/cabinet/`: профиль/вход, вкладки «Замечания»/«История»/«Админ»
    (админ-вкладка только для роли `admin`), фильтры и пагинация поверх
    `GET /api/remarks`/`GET /api/history`, действия по строкам
    (publish/unpublish/delete/history) через `PUT`/`DELETE
    /api/editor/...`, откат через `POST /api/history/{id}/revert`. Ссылка
    «Открыть» строит `/{docId}/?p=<label>&editor=1&ann=<id>` через
    `metadata.json` дока (с фолбэком на `?page=N` без манифеста).
    Деградирует на офлайн-копии сайта (текст «Нет соединения с сервером»,
    без падений — сеть только к API, viewer без `?editor=1` её не грузит).

Логика URL/режимов
- `?p=<label>` — новый канонический адрес страницы (стадия 2 / B.3, только для
  документов с манифестом `metadata.pages`): `A1`, `A2`, `1`, `2`, … —
  регистронезависимо, резолвится через манифест (`main.js`: `manifestMode()`,
  `indexForLabel`). Пагинация и переход по номеру генерируют `?p=`.
- `?page=N` — легаси-адрес (старая арифметика `physicalStart + N − 1`).
  Всегда поддерживается: без манифеста — это по-прежнему единственный формат
  адреса (поведение бит-в-бит как раньше); с манифестом — резолвится в тот же
  файл, что и раньше, после чего адресная строка нормализуется в `?p=<label>`
  (`history.replaceState`, без лишней записи в историю).
- `?editor=1` — включает editor mode; во всех ссылках пагинации сохраняется `&editor=1`.
- Документ без секции `pages` в `metadata.json` (сегодня — все документы)
  ведёт себя точно как до стадии 2: `manifestMode()` выключен, ни одна из
  веток `?p=`/нормализации не активируется.

Бэкенд API (минимальный сервис и Docker)

    - `POST /api/store` — принять JSON‑объект, добавить служебные поля `receivedAt`/`remoteAddr` и положить в файловое хранилище (`inbox/дата/uuid.json`), логировать путь/размер.

- `scripts/api/.env.sample`

## Ключевые поведенческие моменты редактора
- Нулевая регрессия: весь код редактора активируется только при `editorMode`; вне его DOM/события/сеть не трогаются.
- Подсветка выбранного маркера (`.is-selected`), обновление поп‑апа и позиционирования после изменений.
- Валидация для кнопок: content обязателен; coords обязательны (тип `general` упразднён, см. выше).
- «Показать» обновляет и изначально загруженные замечания (их кружки/поп‑апы) — единая точка upsert.

## Аутентификация и роли

- Вход: личный токен (`POST /api/auth/login`, dev-fallback через `EDITOR_TOKENS`,
  роль всегда `editor`) или Google Sign-In (`POST /api/auth/google`, GIS
  ID-token, верификация `google-auth`, `audience=GOOGLE_CLIENT_ID`).
- Пользователи и сессии — в SQLite (`db.py`, `DB_PATH`, том `redpen_db`), не
  в памяти: переживают рестарт контейнера. `POST /api/auth/logout` удаляет
  сессию и cookie; сессии истекают через 30 дней.
- Роли: `viewer` (по умолчанию после входа через Google) `< editor < admin`.
  `admin` — email в `ADMIN_EMAILS`; `editor` — email в таблице
  `editor_allowlist` (управляется через `GET/POST /api/admin/allowlist`,
  `DELETE /api/admin/allowlist/{email}`, только для `admin`); роль
  пересчитывается при каждом входе. Токен-вход — всегда `editor`.
- CSRF: `GET /api/auth/csrf` (требует сессию) выдаёт токен, привязанный к
  записи сессии в БД; все write-эндпоинты сверяют заголовок `X-CSRF-Token`
  с ним (кроме `login`, для которого сессии ещё не существует).
- Права на эндпоинты: `require_user` (есть сессия) → `require_editor`
  (+ CSRF, роль editor/admin) для записи замечаний/inbox;
  `require_admin`/`require_admin_csrf` для `/logs`, `/api/logs`,
  allowlist-эндпоинтов и `/api/admin/publish-all`.
- Фронтенд: кнопка Google (`redpen-editor-bootstrap.js`, GIS-скрипт
  подключается динамически только в editor-режиме) + опциональный
  токен-фоллбэк за флагом `window.REDPEN_DEV_TOKEN_LOGIN`; шапка панели
  редактора (`redpen-editor-panel.js`, `#redpen-auth-status`) показывает
  аватар/имя/роль и кнопку «Выйти».
- Подробности и порядок реализации — `docs/editor-improvement-plan.md`,
  `docs/agent-instructions-stage-0-1.md`.

## Кабинет

- Черновики: замечание имеет `status` (`published`/`draft`/`deleted`).
  `POST`/`PUT /api/editor/{doc}/{page}[/{remarkId}]` принимают необязательное
  поле `status` — если не передано, у существующей замечания статус
  сохраняется (PUT без `status` не публикует черновик), у новой — по
  умолчанию `published`. `publisher.render_page` рендерит только
  `published` — черновики никогда не попадают в статический JSON.
- `GET /api/editor/{doc}/{page}` для анонимов/`viewer` отдаёт только
  `published`; для `editor`/`admin` дополнительно включает черновики
  (`draft: true` в каждом элементе). В editor-режиме просмотрщика они
  подмешиваются в `st.page.remarks` и рисуются маркером с пунктирной
  обводкой (класс `is-draft`); в обычном просмотре их нет.
- Списки/история/статистика — `GET /api/remarks`, `GET /api/history`,
  `GET /api/stats`, откат — `POST /api/history/{histId}/revert` (роли и
  формат ответов — `scripts/api/README.md`, раздел «Кабинет»).
- Deep-link из кабинета в редактор: `?ann=<id>` в URL страницы выбирает
  маркер и подгружает его в форму (тот же путь, что клик по маркеру);
  молча ничего не делает, если id не нашёлся. Чекбокс «Черновик» в панели
  редактора отправляет явный `status` при сохранении.
- Подробности реализации — `docs/agent-instructions-stage-3.md`,
  `docs/stage-3-progress-log.md`.

## Связанные файлы конфигурации/оркестрации
- `docker-compose.yml` — сервисы `frontend`, `api`, `caddy`, `content-sync`; тома
  `redpen_public` (статика сайта; и `content-sync`, и `api` пишут в него —
  `api` только в `*/remarks/`, `content-sync` — во всё остальное, см.
  ниже), `redpen_data`/`redpen-publish` (рабочая копия для CLI-импорта/экспорта
  и inbox) и `redpen_db` (SQLite: users/sessions/allowlist + замечания);
  переменные окружения для CORS/доменов и аутентификации (`GOOGLE_CLIENT_ID`,
  `ADMIN_EMAILS`, `EDITOR_TOKENS`) и публикации (`PUBLISH_DIR=/srv/public` у `api`).
- `content-sync/` — тянет `redpen-publish` из git и синхронизирует его в
  `redpen_public` (`rsync -a --delete`), **кроме** `*/remarks/`
  (владелец — `api`; исключено из `--delete` и из копирования, чтобы не
  затирать то, что пишет `publisher.py`); после синка чинит владельца
  `remarks/` (`chown 10001:10001`) для новых/старых docId.
- `caddy/` — конфигурация реверс‑прокси (внешний каталог, путь проброшен в контейнер `caddy`).

## Примечания по состоянию интеграции
- Режим «Отправить» в редакторе ходит в реальный API (не мок): аутентификация,
  CSRF, роли и optimistic locking (409) реализованы — см. «Аутентификация и роли».
- Все функции просмотра не зависят от редактора: без `?editor=1` редакторский код не активен.
- Замечания — в SQLite, канон; статические `page_NNN.json` — производный рендер
  (`publisher.py`), правки видны на сайте сразу после записи в БД, без
  git-цикла публикации контента.
- Кабинет `/cabinet/` ходит в реальный API так же, как редактор
  (сессия+CSRF); чёрновиковый цикл (создание → видимость только
  editor/admin → публикация/откат) сквозной от `db.py` до фронтенда,
  покрыт тестами (`test_cabinet_db.py`, `test_cabinet_api.py`,
  `test_api.py`) и проверен вручную (см. `docs/stage-3-progress-log.md`).
