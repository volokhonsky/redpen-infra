# Где что живёт: карта системы RedPen

Один вопрос — один ответ: какой адрес что отдаёт, каким кодом и откуда берёт
данные. Быстрый вход в проект — корневой `CLAUDE.md`; раскладка каталогов и
конвейер — `docs/README.md`; эндпоинты API — `scripts/api/README.md`.

Документ переписан 2026-08-30. До этого он пытался пересказывать всю систему
и разошёлся с ней примерно на 40 %: описывал эндпоинты `/api/admin/allowlist`
и `ADMIN_EMAILS` (упразднены моделью анонимности), git submodules (не
используются), удалённый `generate_remarks.py` и режим редактора в старом SPA
(снесён). Пересказ здесь больше не ведётся намеренно: два источника, из которых
один ложный, хуже одного.

## Что отдаётся читателю

| Адрес | Что это | JS |
|---|---|---|
| `/` | титульная: выбор книги, статистика, блок блога | — |
| `/blog/`, `/blog/<slug>/` | блог (`scripts/blog.py`) | — |
| `<doc>/index.html` | оглавление книги (`page_html.render_toc`) | `legacy-page-redirect.js` |
| `<doc>/pages/<label>/index.html` | страница разбора — основной и единственный путь читателя | `redpen-categories.js`, `redpen-markers.js`, `page-view.js` |

Читательский путь **не делает ни одного сетевого запроса**. Замечания страницы
лежат в ней самой, инлайновым блоком
`<script type="application/json" id="redpen-page-data">`; `remarks/page_NNN.json`
рядом — тот же массив для внешних потребителей и офлайн-архива, но просмотрщик
читает не его. Отсюда правило `publisher.py`: на каждую правку переписать и
JSON, и HTML страницы.

Адресация: `<label>` — читательский номер из манифеста `pages[{file,label}]` в
`metadata.json` (`A1`, `A2`, `3`, `4`…), а не имя файла. Старые адреса
(`?p=`, `?page=`, `#pageN`) переадресует `legacy-page-redirect.js`;
`<doc>/annotations/...` — постоянный 301 в nginx (`frontend/default.conf`).
Фильтры показа: `?tags=`, `?notags=`, легаси `?showDrafts=1`, `?only=<id>`.

## Что отдаётся участникам

| Адрес | Что это | Данные |
|---|---|---|
| `/app/` | редактор: карточка замечания, доска параграфов, очередь приёмки, экран страницы со сканом | только API |
| `/cabinet/` | кабинет: списки замечаний и ревизий, роли, приглашения, результаты опроса и пул | только API |
| `/survey/` | опросник: оценка замечаний людьми **вне** круга, входа не требует | только API |

Все три точки входа устроены одинаково: свой html/js/css, ноль общего DOM с
просмотрщиком. Первые две входят через `redpen-auth.js`; опросник не входит
никуда — респондент называет псевдоним и опознаётся заголовком
`X-Survey-Token` (`docs/anonymity-model.md`, «Анонимные респонденты опроса»).
Единичное замечание ни одна из них не рисует заново: все показывают во фрейме
читательскую страницу с `?only=<id>` (`templates/js/redpen-preview.js`). Экраны редактора —
`#/` (параграфы), `#/section/<doc>/<id>`, `#/queue`, `#/page/<doc>/<pageKey>`,
`#/ann/<doc>/<pageKey>/<remarkId>`.

Единственное место, где замечание **создают** и **двигают маркер** —
`#/page/...`. До 2026-08-30 это умел только старый SPA
(`document_index.html?editor=1`); он снесён вместе со своими семью скриптами.

## Кто кому пишет

```
человек в /app/ ────┐
агент по токену ────┼──▶ API (FastAPI) ──▶ SQLite: канон замечаний
кабинет ────────────┤       │              (remarks + remark_history +
человек в /survey/ ─┘       │               remark_tags/ratings/notes,
   (без входа)              │               users/sessions, sections,
                            │               rating_pool + survey_*)
                            │
                            └─▶ publisher.py на каждую мутацию:
                                  remarks/page_NNN.json  +  pages/<label>/index.html
                                  (том redpen_public)

git redpen-publish ──▶ content-sync ──▶ тот же том, но КРОМЕ */remarks/:
                                        их владелец — API
```

`build_website.py` собирает всё, кроме замечаний: шаблоны, картинки, текст,
манифест страниц, страницы читателя, оглавление, титульную, блог, sitemap,
`/app/`, `/cabinet/` и `/survey/`.

## Что важно не сломать

- **Просмотрщик не ходит в сеть.** Инвариант продукта: сайт работает с флешки
  и офлайн. Проверяется `tests/manual/page_view_markers.py`.
- **`compute_page_sha` заморожен.** Он считается по `render_page()` и намеренно
  остался в именах, действовавших до переименования сущности (`annType`,
  `main`/`comment`). Это вход оптимистической блокировки: сдвиг хеша выдаёт 409
  всем открытым сессиям редактора. Наружу этот массив не отдаётся.
- **Оценки и комментарии в статику не попадают никогда** и ревизиями не
  являются — сводятся только на чтении, в `GET /api/remarks/.../timeline`.
- **Личность не восстанавливается.** Система хранит о человеке
  `HMAC(IDENTITY_PEPPER, google_sub)` и выбранный им псевдоним; email, имя и
  аватар не читаются из токена вовсе. Нормативный документ —
  `docs/anonymity-model.md`, и ослабление схемы начинается с правки его, а не
  кода.
- **Каталоги `<doc>/remarks/` и `<doc>/pages/` принадлежат API** (uid 10001).
  content-sync исключает первый из rsync и восстанавливает владение обоими
  (`content-sync/entrypoint.sh`).
